# smpp-companions

> Русский перевод [README.md](README.md); при расхождении истина в оригинале.

**Security-transit-прокси протокола SMPP 3.4** с открытым кодом. Он встаёт между вашими
SMS-клиентами (ESME) и SMSC, так что каждый bind и каждое сообщение пересекают одну
контролируемую, наблюдаемую точку — вместо пути напрямую к SMSC. Построен на Netty и Spring
Boot 4 (JDK 25): headless, настраивается оператором, fail-closed — неверная конфигурация
отказывает при старте, а не в продакшене.

## Для чего это?

- **Центральная проверка учётных данных** — пароль каждого SMPP-бина проверяется в вашем IdP
  (OIDC resource-owner password grant) до того, как прокси соединится с SMSC.
- **Legacy-клиенты не трогаем** — ESME, говорящие на plain SMPP, продолжают работать;
  безопасность всего, что за ними, берёт на себя прокси.
- **Безопасный транзит в трёх формах** — Mode B (открытый пароль), Mode A (one-way TLS между
  уровнями прокси), Mode C (mTLS) — плюс структурированные JSON-журналы и read-only
  endpoint `/metrics`.

## Попробуйте

Быстрее всего увидеть прокси в работе — в песочнице. Для каждого варианта использования
(роль + режим) есть своё пошаговое руководство — сборка, подъём стенда, запуск прокси и
наблюдение, как реальная цепочка Kannel сопрягается через него:

- **[`reverse`, Mode B](sandbox/runbooks/reverse-mode-b.ru.md)** — legacy-клиенты соединяются
  напрямую с единственным экземпляром прокси с открытым паролем; каждый bind проверяется в
  вашем IdP.
- **[`forward` + `reverse`, Mode A](sandbox/runbooks/forward-reverse-mode-a.ru.md)** — два
  экземпляра прокси: открытый пароль на доверенном участке, затем one-way TLS через
  недоверенный.
- **[`forward` + `reverse`, Mode C](sandbox/runbooks/forward-reverse-mode-c.ru.md)** — те же
  два участка, но между прокси mTLS; шлюз — сам TLS-handshake.
- **[sandbox/README.ru.md](sandbox/README.ru.md) — песочница подробно.** Что такое стенд, как
  его поднимать, сценарии проверки корректности, гид по отладке.
