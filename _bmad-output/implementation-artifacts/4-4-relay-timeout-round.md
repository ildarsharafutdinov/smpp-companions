## Intent

**Problem:** Four timeout-shaped holes pin the pre-couple window open indefinitely. (1) `companion.bind.adjudication-deadline` (default 4s) ships validated but UNARMED — its only consumer is `RequestContext.deadline` (`BindInterceptor.java:331`), so a never-settling verifier future pins the registry entry, the original bind frame, and the legacy client's socket until the client gives up (ledger F14). (2) The per-bind egress `Bootstrap` sets no `CONNECT_TIMEOUT_MILLIS` — a blackholed SMSC target hangs the legacy socket ~30s on the Netty/OS default, ~7.5× PERF-3's 2–5s fail-closed budget (F10). (3) A decoded `bind_resp` arriving on the INGRESS leg is released and silently dropped (`BindInterceptor.java:249-257`) — no AD-32 bare-close, no test for either window (F1). (4) An accepted-but-never-binding socket holds its `companion.memory.concurrent-pairs` cap slot forever — no idle handler exists anywhere in `relay/` (F13 residue).

**Approach:** Arm all four bounds relay-side, fail-closed, on the ingress event loop — no pipeline surgery, no port-contract changes. The adjudication deadline becomes a per-bind deny+teardown timer routed through the single-sited `RelayStateManager.beginTeardown` (AD-32 case-3 ordering: remove+mark → `cancelHttp()` → zeroize → close), answering the client with the existing AD-33 collapsed generic non-ROK `bind_resp`; the egress dial gets `CONNECT_TIMEOUT_MILLIS` derived from `adjudication-deadline` (no new knob — the F13 one-number precedent); the ingress `bind_resp` drop becomes an AD-32 bare-close (never forward — a forwarded pre-flip ROK would couple the pair without SMSC consent); and a pre-couple window watchdog (armed at `channelActive`, re-checked at fire time, never firing post-couple) reclaims cap slots from never-binding sockets. Prove with the deterministic-seam idiom (injectable timer arm — capture-and-fire; no real wall-clock waits), then close the ledger: resolution markers for F14/F10/F1/idle plus the unmarked 4.1/4.2/4.3 closures, each citing a biting test.

## Spec Change Log

## Design Notes

- **F14 fork — deny+teardown, not complete-exceptionally-at-deadline.** Completing the future exceptionally from the relay side would make the relay a second author of the verifier's future (two settlers with different semantics, and the port says nothing about relay-side completion). Deny+teardown reuses the already-convergent machinery: `cancelHttp()` settles the pin `DenyIndeterminate` (3.2 AC5 guarantee, `RopcBindCredentialVerifier:859-876`), the continuation re-checks and no-ops, and the wire answer comes from the one existing synthesizer. The timer never fabricates a `Verdict` — hence no `onBindReject` (observer contract: verifier-returned Verdicts only; the deadline deny is log-distinguishable, enum-identical `BIND_REJECTED`).
- **F7 residue — port stays silent.** Amending `VerdictRequest` to promise settlement on `cancelHttp()` is an AC8-ratified-surface change → Ask-First, not done here. The armed deadline consumes `cancelHttp()` via `beginTeardown`; a discipline-violating verifier can still strand one pooled buffer per abandoned adjudication — documented residual, exactly as the ledger anticipates.
- **Timer mechanism — event-loop schedule + injectable seam.** Production arms per-channel on the ingress event loop (same thread as the handshake — no cross-thread races, no `Clock` bean widening, 4.3's reservation respected). Tests capture the scheduled task and fire it manually — deterministic, no wall-clock waits. The seam is one small interface in `relay/`; if implementing it cleanly requires touching `RequestContext` or the verifier surface → that is the Ask-First HALT, not a design liberty.
- **Connect bound derived, not a knob.** `CONNECT_TIMEOUT_MILLIS = adjudication-deadline` millis. F13's precedent deleted a second knob for one number ("two knobs = drift surface"); the deadline IS the whole pre-couple auth budget, so the dial bound is the same number. Worst-case client answer ≈ deadline + ε (deny write is immediate on connect-fail) — inside PERF-3's configured 2–5s family.
- **Idle watchdog — window bound at `channelActive`, not an `IdleStateHandler`.** AD-2 forbids live pipeline surgery, and a pipeline-resident idle handler cannot distinguish pre-couple from PERF-2's legitimately-idle coupled pairs without exactly that surgery. A scheduled watchdog cancelled/no-op at couple bounds connect→couple only, and for free it also bounds the silent-SMSC post-forward window (R32 sub-window RELAY-021 does not cover). Default 30s: well above the legitimate cold path (≤2s) + deadline (4s), well below "forever"; operator-tunable because slot-reclaim cadence is an ops concern distinct from the PERF-3 auth budget.
- **Quiesce outer bound shape** follows ledger :615-617's candidate: bounded await + WARN-and-proceed, mirroring `release()`'s defensive arm — fail-closed in outcome (shutdown proceeds) rather than fail-fast.
- **Catalog honesty.** RELAY-020-as-written is already green (connect-refused fails fast without the option); citing it for this story's work would pass vacuously — hence fresh rows (deadline arm, idle watchdog, RELAY-020 blackhole amendment) in T6 rather than borrowed cites.
