# Story 3.2: OIDC ROPC bind adjudicator — production adapter behind the AD-12 port

Status: ready-for-dev

> **The Epic 3 production-security slice.** Story 2.1 shipped the AD-12 port types + an always-allow stub in `main` and ratified the contract shape against real Keycloak 26.7.0 with a *test-tier* slice (`RopcSlice`, under `proxy/src/test`). This story ships the **production ROPC adapter** in `proxy/src/main/.../security/`, wired via Spring DI behind the **ratified-immutable port** (AC8, 2026-08-10 — "wire, never re-author"), plus the `companion.*` config surface it needs. **Scope discipline (non-negotiable): `proxy/src/main/.../relay/` is NOT modified** (epics.md §Epic 3: the swap is "behind the unchanged AD-12 port via Spring DI"); the forward-role acceptor widening that would exercise the adapter through a live relay belongs to the NEXT story (3.3). The load-bearing evidence is **AC2** (the AD-11 verdict mapping, incl. the 429/404/403 ledger refinement) and **AC5** (AD-28(4) concurrency + the F7 settlement-on-cancel decision).

## Story

**As a** proxy operator running Keycloak (or any OIDC provider with Direct Access Grants),
**I want** every accepted legacy bind's password-grant adjudicated by a real ROPC call to my provider — with local Nimbus JWKS defense-in-depth, RFC 7662 introspection for opaque tokens, fail-closed on every indeterminate condition, and zero credential bytes surviving the adjudication —
**so that** my proxy tier stays credential-free (FR-SEC-1/AD-10): it brokers and delegates trust instead of holding it, denies closed when the provider is unreachable or ambiguous (FR-SEC-5/AD-11), and never leaks a working carrier credential from a compromise.

2. **[AC2] AD-11 verdict mapping — the normative production table.** The token-endpoint call's outcome maps to `Verdict` exactly per this table (this RESOLVES deferred-work "429/404/403 → DenyInvalid misclassification"): `DenyInvalid` is reserved for the provider's **positive invalid-credential signal** — HTTP 401 (a bare 401 from a token endpoint IS a positive auth-layer rejection per RFC 6749 §5.2, even with an unparseable body), or HTTP 400 whose parsed OAuth `error` is `invalid_grant` or `invalid_client` (2-1 fixture finding #6: bad user → 400 `invalid_grant`, bad client → 401 `invalid_client`; its rule is "do not key on 401 **alone**" — bad-user credentials arrive as 400, so map by error semantics: parse the 400 body as JSON and key on the `error` field). **Everything else is `DenyIndeterminate`**: 200-with-non-JWT/HTML/empty body, 200-with-malformed-JWT, 3xx, any other 4xx (incl. 403/404/429 and 400s with other/absent error codes — rate-limit, config and authorization errors are not credential verdicts), 5xx, timeout, network error, cancellation, admission saturation, and scope shutdown. **DENY always wins on disagreement**: a 200 verdict overridden by failed local JWT verification (signature/iss/aud/exp/nbf/typ/kid) → `DenyIndeterminate` (defense-in-depth failures are *unverifiable*, not *invalid* — matches the ratified slice). Introspection: **only** HTTP 200 + JSON + boolean `active:true` → `Allow`; every other outcome (incl. `active:false`) → `DenyIndeterminate`. `kid` absent from cached JWKS → `DenyIndeterminate` + background refresh scheduled; **no foreground refresh-and-retry on the bind path**. Every row of this table has a test with a RED-on-neuter control (bind the exact bad response through the in-process IdP stand-in, never a removed code path). **Supersession note:** this refined mapping intentionally supersedes the shorthand "4xx → `DenyInvalid`" in the spine's AD-12 ratification bullet and the `Verdict.DenyInvalid` javadoc example ("e.g. an IdP 4xx") — the port types stay untouched (AC8-immutable; the javadoc example is stale by design), and the refinement is recorded as a dated entry appended to the architecture `.memlog.md` when T3 lands. Wire impact: none (AD-33 collapses both `Deny*` permits identically); the distinction surfaces only in logs/metrics labels. *(AD-11; ARCHITECTURE-SPINE.md:130–133; deferred-work §2.1 item 1.)*

3. **[AC3] JWT defense-in-depth via cached JWKS (Nimbus).** On a 200 JWT verdict the adapter locally verifies with Nimbus JOSE+JWT (already `com.nimbusds:nimbus-jose-jwt:10.9.1` in `proxy/build.gradle.kts`; floor ≥10.0.2, CVE-2025-53864, enforced by `smpp.dependency-floors`): signature against the **cached** JWKS, `iss` == the configured issuer, `aud` containing the configured client-id, `exp`/`nbf` per clock (NTP precondition A-4), `typ` header per RFC 8725 §3.9 (absent → tolerated, present-but-unexpected → deny — **verify the pinned fixture's actual `typ` value live before hardcoding**; do not trust training data for the literal). The JWKS cache is an `AtomicReference<JWKSet>` swapped **whole** on successful refresh (never nulled before a successful fetch — deferred-work §2.1 item 6b), refreshed by a hand-rolled virtual thread on a `ScheduledExecutorService` owned by `security/` (**not** `@Scheduled`, and **not** through the adjudication pool or its admission semaphore — §2.1 item 6a, Task 4) with TTL/refresh-ahead (config, spine-deferred values → dev-selected defaults with positivity guards). **No verdict cache of any kind; introspection results never cached** (AD-12). *(AD-12; ARCHITECTURE-SPINE.md:135–142; AD-28(2) ibid:226–229.)*

4. **[AC4] Opaque-token fallback = RFC 7662 introspection, cancellation-visible.** When the 200 body is not a locally-verifiable JWT (opaque token), the adapter calls the provider's introspection endpoint (endpoint URIs come from OIDC discovery of `provider-url` — no per-endpoint override keys); the introspection `sendAsync` future is registered in the same active-call slot as the token call so `cancelHttp()` aborts it too (2-1 review fix **F3**). Introspection verdict per AC2's table; never cached. Operators should prefer JWT issuance (introspection is online-only with no offline cryptographic backstop — emit that guidance in the config key's javadoc/docs comment, not runtime noise). *(AD-12; 2-1 Dev Notes F3.)*

5. **[AC5] Concurrency, cancellation, and the F7 settlement decision.** Entry bounding per AD-28(4): a **single bounded hand-managed VT `ExecutorService` owned by `security/`**, sized by `oidc.max-in-flight`, admission via `tryAcquire` semaphore — **a saturated pool returns `DenyIndeterminate` without starting any wire call** (2-1 review fix **F2**: `sendAsync` deferred until AFTER `tryAcquire`); spawning a VT per bind outside this pool is forbidden; never `@Async`. `verify()` never blocks the caller's thread (the relay pins this: `BindInterceptorTest`'s class-level `@Timeout` with `SEPARATE_THREAD` mode is the anti-blocking pin). Inside one adjudication the fan-out uses **JDK 25 StructuredTaskScope (JEP 505, fifth preview)** with the `open(Joiner)` API — `StructuredTaskScope<T,R>`, `static open(Joiner)`, `fork(Callable)`, `join()`, `close()`, `Joiner.awaitAllSuccessfulOrThrow()` — **NOT the JDK-21/22 `new ShutdownOnFailure()` subclass pattern** (2-1 verified the live-JDK-25 shape; also web-confirmed vs JEP 505). `RequestContext` is re-bound on the pool thread **via the same `ScopedValue` handle passed to `verify()`** (`ScopedValue.where(ctx, rc).call(...)`), never `ThreadLocal`. **Capture rule: read `ctx.get()` synchronously inside `verify()` on the caller's thread** — the relay binds `REQUEST_CONTEXT` only for the dynamic extent of the call (`BindInterceptor.java:256-257`), so dereferencing the handle on a pool thread without re-binding throws `NoSuchElementException`; F12's `requireNonNull(ctx)` guards the handle, not bound-ness. The scope is **shuttable from the teardown path** (AD-25: case-3 teardown shuts the adjudication's STS) and `cancelHttp()` binds to `HttpClient.sendAsync(...).cancel(true)` aborting the real wire exchange (2-1 verified `MinimalFuture.cancel(true)` → `MultiExchange.cancel` → `connection.close()`, requires `mayInterruptIfRunning==true`). **F7 DECISION (this story owns it): the production adapter GUARANTEES `future()` settles (with `DenyIndeterminate`) after `cancelHttp()`** — an adapter-level contract that resolves the relay's cancelled-verdict frame-leak (2-2 F7) at the source **without amending the AC8-immutable port** (the port is silent on settlement; promising it is additive). Proven by a test asserting settlement + `CancellationException` in the aborted wire future's cause chain (reuse 2-1's `RecordingHttpClient` delegating-wrapper pattern and the "assert anywhere in the cause chain" rule). *(AD-4, AD-5, AD-25, AD-28(4), AD-32; ARCHITECTURE-SPINE.md:82–90, 214, 226–229, 253; deferred-work 2-2 F7.)*

6. **[AC6] Secret hygiene — raw-byte encoding and token zeroization.** The ROPC form encodes the password **from the raw backing bytes** (`value.array()`/`arrayOffset()`/`length()`), **never `toString()`** — the `AsciiString.toString()` lazy-immortal-String hazard (2-1 F1: the throwaway slice's `pw.toString()` shortcut is FORBIDDEN in production). The **password's `zeroize()` stays CALLER-OWNED** (relay `BindInterceptor` continuation `finally` + `cancelAndWipePending`, settled 2.2 T7 — the adapter reads the password asynchronously while its future is pending, so it must NOT zeroize at `verify()`-return; codec `SmppBytes` copies C-octets so a later wipe cannot corrupt the forwarded frame). The adapter owns and zeroizes **its own** secret material on every completion path — access-token bytes and any form-encoded request buffer in `char[]`/`byte[]`, never `String` — including the use-after-close hardening: `try/catch(RejectedExecutionException)` → release permit + zeroize (deferred-work §2.1 item 2). `NoStringFromPasswordTest` (CODEC-024 P2 scan, already rooted on `security/` main) passes over the new adapter source unchanged, with a fresh mutation control proving it bites on the adapter. *(AD-10(3), AD-12 secret-hygiene; PRIV-1; deferred-work §2.1 items 2–3.)*

7. **[AC7] Provider link TLS — https-only, AD-13/26 trust posture, AD-34 intersection, RFC 8705.** The proxy→provider link uses a single shared `java.net.http.HttpClient` with an `SSLContext` built from operator config: **trust = a dedicated IdP trust store (file-path-injected, AD-18) with the full AD-13 posture — never JDK `cacerts`, fail-fast on absent/empty/wrong-format/zero-`trustedCertEntry`** (reuse `CompanionConfigValidator.requireTrustStore`'s 5-state check pattern); **client auth = exactly one of** `client_secret` (file-path) **or** mTLS keystore (RFC 8705 `tls_client_auth`, path+password leaf) — exactly-one-of enforced fail-fast. Non-`https` `provider-url` already fails (SEC-053/054) — keep. **At startup, intersect `companion.tls.*` configured suites with the IdP client `SSLContext`'s supported suites; empty intersection → fail-fast** (this discharges deferred-work **D2/AD-34** for the IdP mTLS client context — the ingress/egress SMSC contexts land with story 3.3's TLS work). Startup OIDC discovery of `provider-url` (`/.well-known/openid-configuration`) runs **once at adapter bean initialization** (constructor/init — a refusal surfaces as the standard Spring startup failure, non-zero exit) and is **hard-required**: discovery failure → refuse to start (fail-closed: a misconfigured provider URL is the common case; a provider outage blocks binds either way per A-2). If `grant_types_supported` omits `password` (DAG off-by-default since KC 26.2) → **loud warning, defer to runtime** (grant-type error → DENY per AC2). **Existing full-context tests survive this via a test-support HTTPS stand-in discovery server** (Project Structure Notes): `TestCompanionConfigs.forwardA()/forwardC()` default `provider-url` to the stand-in (live Keycloak tests override with the fixture URL), so the four existing full-context boots (`BootstrapLifecycleTest`, `RelayServerLifecycleTest`, `DirectMemoryBudgetStartupCheckTest`, `CompanionTlsBindingTest`) stay green against a bootable forward cell — no test is weakened or skipped. *(AD-12, AD-13, AD-26, AD-34; ARCHITECTURE-SPINE.md:135–147, 216–219, 260–263; deferred-work 1-3 D2.)*

## Dev Notes

### Architecture compliance (MUST follow)

- **AD-12 (ROPC adjudication, spine:135–142)** — token-endpoint status 200/401 **is** the verdict; local JWT verify is defense-in-depth (AD-11 precedence, DENY wins); **discard the token, relay the ORIGINAL bind** (the adapter never substitutes the verdict for the SMSC's own check — the relay already forwards `originalFrame()` verbatim); **re-validate every bind — no verdict cache, cache JWKS only; introspection never cached**. Port is immutable since AC8 (2026-08-10): `VerdictRequest verify(BindCredential, ScopedValue<RequestContext>)`, `future()`/`cancelHttp()`, sealed `Verdict permits Allow, DenyInvalid, DenyIndeterminate`, **no Throwable/Nimbus/free-form-reason type crosses the port** — the adapter absorbs Nimbus.
- **AD-11 (fail-closed, spine:130–133)** — every auth-adjacent decision denies on indeterminate; AC2's table is the exhaustive instantiation. Unknown `system_id` → DENY (routing-miss) is **relay/story-3.3 territory** — NOT this story.
- **AD-4 / AD-28(4) (no blocking on event loops; bounded VT pool)** — all adapter I/O off event loops; single bounded hand-managed VT pool owned by `security/`, config-sized, fail-closed on saturation; **never `@Async`, never a VT-per-bind outside the pool, never `CallerRunsPolicy`**.
- **AD-5 (STS + ScopedValue, spine:87–90)** — STS structures the fan **within one adjudication**; the pool gates entry — STS does not replace bounding. Preview confinement: STS lives in the control plane (`security/` + `bootstrap/`) only. JDK 25 STS = JEP 505 fifth preview (`open(Joiner)` API — see AC5); ScopedValue is final (JEP 506). Pin risk is absorbed: `smpp.java-conventions` already runs `--enable-preview` process-wide and 2.2 T1's compiler gate enforces it.
- **AD-10(3) / PRIV-1 (credential-free at rest)** — runtime holdings are exactly: OIDC client credential (file-path), cached JWKS public keys, per-bind password in memory during adjudication+forward (never persisted/logged/cached), own TLS keys. Zeroization events: adjudication completion, connection teardown, JVM shutdown, exception paths.
- **AD-13 / AD-26 (trust posture)** — IdP trust store never `cacerts`; PKIX defaults, no custom chain-validation code, no `PKIXBuilderParameters` overrides.
- **AD-22 / AD-28(2) (shutdown ordering, spine:196–199, 226–229)** — stop JWKS refresh **before** closing the JWKS cache; DENY in-flight adjudications on shutdown; pool drain = `shutdownNow()` + await with fail-closed log.
- **AD-25 (teardown race, spine:214)** — case-3 teardown shuts the adjudication's STS and calls `cancelHttp()` (the relay's `BindInterceptor.teardownForPreCoupleViolation` + `cancelAndWipePending` already do this from the caller side — `BindInterceptor.java:348-359`); a late verdict reaching a torn-down entry is a no-op relay-side. The adapter's settlement guarantee (AC5/F7) makes the "late verdict" window settle cleanly.
- **AD-27 (observer contract)** — `onBindReject` fires only for actual `Verdict` values returned by the verifier (relay-side, `BindInterceptor.java:314`); the adapter changes nothing here — but it must never return `null` from `verify()` and never complete `future()` exceptionally-as-normal-flow (relay treats exceptional/null as fail-closed deny — `BindInterceptor.java:258-280`; the adapter settles every future with a `Verdict`).

### Verdict mapping — normative quick table (AC2)

| Token endpoint outcome | Verdict |
|---|---|
| 200 + locally-verifiable JWT (defense-in-depth passes) | `Allow` |
| 200 + opaque token → introspection 200+JSON+`active:true` | `Allow` |
| 401 · 400 with `error` ∈ {`invalid_grant`, `invalid_client`} | `DenyInvalid` |
| 200 non-JWT/HTML/empty · malformed JWT · 3xx · any other 4xx (403/404/429, 400 other error) · 5xx · timeout · network error | `DenyIndeterminate` |
| 200 JWT but sig/iss/aud/exp/nbf/typ fail · kid-miss | `DenyIndeterminate` (DENY wins; background JWKS refresh, no foreground retry) |
| Introspection anything ≠ 200+JSON+`active:true` (incl. `active:false`) | `DenyIndeterminate` |
| Admission saturation · `cancelHttp()` · scope/executor shutdown | `DenyIndeterminate` (saturated: **no wire call started**) |
