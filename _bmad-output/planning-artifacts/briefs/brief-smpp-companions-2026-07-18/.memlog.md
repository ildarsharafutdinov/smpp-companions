- (decision) Create intent; primary input = brainstorm-intent.md. Brief captures the product story (why/for-whom/what-it-is); architecture detail stays in the intent doc -> PRD/addendum. PRD run parked at prds/prd-smpp-companions-2026-07-18/ to resume after the brief firms up framing.
- (decision) Product identity: OSS SMPP security proxy, modern tech-stack, inspired by Cloudhopper/jSMPP lineage but built fresh. Headless — no UI (operator-configured). Stakes = PET PROJECT (right-size: lean, honest, no investor/moat rigor).
- (decision) Audience/scope: serves BOTH sides of the SMPP wire — enterprise connecting to a carrier (proxy1/ingress role) AND carrier accepting connections (proxy2/egress role). One codebase, two deployment roles (maps onto the two-proxy architecture).
- (decision) Core value + form: secure SMPP over the internet WITHOUT modifying legacy systems (legacy stays SMPP 3.4 / password-grant / no-TLS as-is; proxy absorbs + secures transit). Deployment = Docker image OR embedded library (confirming both first-class).
- (decision) Tech stack = MODERN JVM (not off-JVM): JDK 25 + latest Netty (wire), virtual threads + structured concurrency (Project Loom) where applicable, GraalVM native-image as a perf fallback. Stays in the Cloudhopper/jSMPP contributor ecosystem while modernizing. Implementation detail -> addendum; 'modern JVM stack' = brief positioning line.
- (decision) Both deployment modes FIRST-CLASS: clean library core + thin Docker image wrapper.
- (decision) Motivation is REAL (scratch-your-own-itch), not theoretical. Concrete pain detail pending (asking).
- (decision) Itch (concrete): add features (security first) to an EXISTING legacy SMPP system WITHOUT touching/modifying it. The proxy is a NON-INVASIVE AUGMENTATION layer; security is the first feature set, the bolt-features-onto-untouchable-legacy pattern is the real itch.
- (decision) Success = PORTFOLIO PIECE: real, well-built, shippable OSS demonstrating modern Java (concurrency+networking+security). Author uses it to scratch the itch; adoption is a bonus, not the goal.
- (decision) Scope boundaries CONFIRMED: MT-only + SMPP 3.4 (no SMPP 5.x, no MO/inbound). Other potential-outs (mgmt API, metrics/observability, Windows build) [ASSUMPTION]-tagged as not-in-v1 pending confirm.
- (decision) Name/framing = COMPANIONS (plural) — a FAMILY of non-invasive augmentation modules for legacy SMPP. v1 = the security-transit companion; more companions will follow (logging/audit, rate-limit, protocol translation...). Matches the 'add features (plural) to legacy without touching' itch.
- (decision) v1 non-goals CONFIRMED: no management API, no metrics/observability, no Windows build (future companions may take some).
- (decision) Default authority provider (v1) = KEYCLOAK (OSS IdP): password-grant validation + mTLS client-cert authn. Open: Keycloak authenticates certs but doesn't issue them -> cert-issuing CA is separate (operator/CA concern); and whether v1 bundles Keycloak config or just the integration.
- (change) CORRECTION: Keycloak is NOT part of the project. Authority provider is EXTERNAL/BYO — operator runs it; Companions consumes it. Keycloak = reference/intended provider, pluggable, not bundled.
- (change) CORRECTION: Certificates are ENVIRONMENTAL — Companions does not issue certs and is agnostic to who issues them; expects valid certs present at runtime (deploy-time bake is one valid source, not mandated). Resolves the cert-issuance open question -> operator concern, out of scope.
- (decision) Future companions NAMED: (1) modern JVM SMPP library (Cloudhopper/jSMPP successor; likely the shared foundation others build on; v1 SMPP internals should factor toward it); (2) JMeter load-testing plugin for SMPP. Earlier candidates (logging/audit, rate-limit, protocol translation) stay on the table. v1 architecture stays modular.
- (change) PRECISION: Cloudhopper and jSMPP are INSPIRATIONS only (conceptual lineage, contributor-ecosystem familiarity) — NOT forked or reused code. Everything built FROM SCRATCH for JDK 25. No derivation, no licensing/attribution entanglement. Strengthens portfolio story (original work). Corrects 'stands on shoulders'/'successor' wording that implied derivation.
- (decision) Authority-provider contract = OIDC (the standard Keycloak implements). Companions conforms to OpenID Connect for the password-grant check — no bespoke interface, any OIDC provider drops in. RESOLVES the last open question; all brief open questions now closed.
- (event) Brief FINALIZED — content approved across Discovery, polish applied (editorial structure + prose, substance preserved), status set to final. All open questions resolved (Keycloak external; certs environmental; authority-provider contract = OIDC).
