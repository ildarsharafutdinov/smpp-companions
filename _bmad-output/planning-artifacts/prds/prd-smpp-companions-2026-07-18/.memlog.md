- (assumption) Research finding (7-agent sweep, 16+ cited sources, saved .perf-anchors.json): NO published benchmark exists for an SMPP proxy / stateless two-leg relay with mTLS — every public SMPP number is a client<->server codec or single-session round-trip (smpp-core, jSMPP, Cloudhopper). Companions publishing its own harness-measured relay benchmark would be a first-of-kind portfolio contribution. Codec is ~60x faster than network (never the bottleneck). Real carrier throughput (Sinch 10 MT MPS/bind, Twilio <=400 MPS/account, 8x8 ~200 MPS/system_id) is 1-3 orders of magnitude below any modern relay ceiling -> the proxy is never the production bottleneck; carrier bind provisioning governs. Therefore the v1 throughput target is about demonstrating HEADROOM/CRAFT, not matching production need. Honest published ceiling without a percentile-table harness: ~25-36K end-to-end (smpp-core 25K single-thread; MockServer ~36K on 6 cores). VT-Netty on JDK 25 held 60K simultaneous conns with zero errors (chrisgleissner, reproducible) -> concurrency/resource IS the flex.

- (decision) Modularity line (Decision A): adopt 'structured for future extraction' path. IN as a maintainability NFR / craft signal: SMPP codec + PDU layer structured as a clean, separable, independently-tested module with documented boundaries. OUT (scope creep): standalone library artifact, extension-point/SPI machinery, deferring proxy features for core purity, any 'pluggable extension points' FR. The proxy ships whole. All siblings (future SMPP lib, JMeter plugin, logging/audit, rate-limit, protocol-translation, metrics) stay explicitly non-v1. Modularity = a quality of the code, NOT a product surface.
- (decision) From-scratch line (Decision B): 'built from scratch, not a fork' applies to the SMPP layer ONLY (codec, PDU model, session/relay logic). MUST use mature libraries for crypto/TLS (JDK SSLEngine or Netty tcnative/BoringSSL) and OIDC (mature JOSE/JWT lib, e.g. Nimbus). Never roll own crypto. Stated as an explicit PRD principle so 'craft' cannot be misread as 'rolled my own crypto'. Specific lib choices -> addendum.
- (decision) PDU model (resolves OQ-2): HYBRID. Proxy inspects/handles ONLY the bind family + unbind(+resp) (for session mgmt + auth); ALL other PDUs are spliced transparently as opaque bytes (not inspected, not filtered). Consequence: MT-only is NOT proxy-enforced (MO would also pass); it is a deployment expectation. deliver_sm/DLRs flow back via the splice. PDU matrix = handled(bind+unbind) vs passthrough(everything else).
